# API 명세 작성 (Write API Spec)

## 목적

API 명세 문서를 생성하거나 업데이트한다. 프론트엔드 또는 팀에게 전달하는 문서다.

## 필요한 입력

- PRD 또는 기능 설명
- 실제 라우터·컨트롤러 코드
- 요청/응답 스키마(DTO, Pydantic model 등)
- 에러코드 정의 (`docs/errors/` 또는 프로젝트 규칙에 따른 경로)
- `AGENTS.md` (경로 패턴, 응답 포맷, 인증 규칙)

## 진행 순서

1. `AGENTS.md`에서 API 경로 패턴과 응답 포맷을 확인한다.
2. 영향받는 엔드포인트를 파악한다.
3. 실제 코드의 요청/응답 스키마에서 필드를 확인한다. 코드에 없는 필드를 만들지 않는다.
4. 다음 항목을 문서화한다:
   - HTTP 메서드, 경로, 인증, 권한
   - 요청 바디 / 쿼리 파라미터
   - 성공 응답 (프로젝트의 공통 응답 래퍼 포함)
   - 에러 응답 (실제 예외 처리 기반)
5. 비즈니스 규칙과 엣지 케이스를 포함한다.
6. 예시 값은 실제 스키마와 일치시킨다.
7. 템플릿을 사용하여 저장한다.

## 출력

```text
docs/api/{domain}/{api-name}.api.md
```

경로는 프로젝트 `AGENTS.md`의 문서 규칙을 따른다.
